# Internal architecture

- `main.py` opens a stdlib-only startup/repair window before importing the optional GUI stack. Missing source-checkout dependencies are installed with a logged retry; frozen builds verify and repair their bundled native runtime offline. `--version` and `--health-check` are non-interactive checks.
- The main desktop UI is a compact, rounded, frameless `PROTEZ` window with a white pixel-sword icon, a moving gradient outline, borderless minimize/close controls, and a short fade-in/out. The pixel font is reserved for the wordmark; source and log text use readable system/monospace fonts. Paste, file, Browse fallback, and optional drag-and-drop remain available. UI logs show timestamps and levels through a queue; processing runs on a worker thread. Results and partial-analysis reports are opened automatically in the system text editor (with an in-app fallback). The Windows executable requests Administrator approval through its application manifest at launch.
- `core.source_input` accepts direct HTTP(S) code links, common GitHub blob/Pastebin pages, and simple `loadstring`/`HttpGet` wrappers. It fetches text only, follows at most four linked layers, caps downloads at 16 MiB with request timeouts, validates redirects, and blocks local/private network targets. It never executes the fetched source.
- `core.deobfuscator` is a bounded static Luau tokenizer and constant-expression evaluator. It folds supported literal/string, arithmetic, bit32, table-concat, and Base64 forms; it never executes the input. Unknown/dynamic expressions are retained unchanged. It is a pattern-based helper, not a general Luau decompiler.
- `core.pipeline` statically cleans the input, then checks for known Luraph VM wrappers before any compilation or sandbox step and writes a clearly labeled static-only report plus wrapper preview; it does not present that preview as reconstructed Luau. Other inputs are validated using compile-only mode and locally captured payloads are explored to a maximum of 6 layers / 20 candidates under a 90-second budget. It retains a valid source fallback and writes a `.luau` result plus JSON analysis report. If the process is elevated, dynamic sandbox execution and tracing are skipped; static analysis and compile-only validation remain available. Syntax validity does not mean full deobfuscation.
- `core.sandbox` runs the generated mock-runtime harness in a separate, time/output-limited process, captures locally produced `loadstring`/`load` payloads, and disables remote HTTP and module access. The Roblox-shaped API is a mock, not an OS-level security boundary; use a disposable account/VM for hostile input.
- When present, `tools/protez-native-host` (or `.exe`) runs the pinned Luau 0.740 compiler and VM. Compile-only checks load bytecode without executing a candidate. The host is built from `native/host.cpp` and compiled with optimization level 0 / debug level 2 for instruction tracing and local/upvalue names.
- The native host uses Luau's `lua_singlestep`/`debugstep` callback and version-pinned internals (`CallInfo.savedpc`, active `Proto`, opcode adapter) to emit bounded instruction events and sampled primitive locals. Full register recovery, CFG lifting, VM-handler recovery, and source reconstruction are not implemented. Recheck the private-internals adapter before changing the pinned Luau tag.
- `core.tracer` streams validated hook/API and optional native VM events into rotating JSONL files rather than retaining the trace in RAM. Stock Luau fallback traces do not include instruction stepping.
- `installer.py` repairs source-checkout dependencies, fonts, and available Luau tools with timestamped logs, subprocess timeouts, and a retry path. The GUI registers bundled Windows pixel fonts as private but enumerable so Tk can select them. Windows release builds bundle the Python runtime, Tk/CustomTkinter resources, pixel fonts, mock runtime, and native host, so the end user does not need to install Python, pip, CMake, or Luau.
- `.github/workflows/windows-installer.yml` builds x64 Windows `Protez.exe` with the sword icon and a `requireAdministrator` manifest, plus a separate elevated `Protez-Setup.exe`. Setup lets the user choose an install directory, verifies the embedded executable by SHA-256, installs/repairs it, and creates Start Menu and optional desktop shortcuts. Only `Protez.exe` is attached to GitHub Releases; the installer remains a CI artifact.
