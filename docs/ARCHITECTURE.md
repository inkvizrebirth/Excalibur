# Internal architecture

- `main.py` opens a startup/repair window before loading the optional GUI. Frozen builds verify and repair their bundled runtime offline. `--version`, `--health-check`, and `--ui-import-check` are non-interactive checks. The import check does not create a window and is not a visual GUI smoke test.
- The desktop UI is compact and square-cornered, with readable system/UI and monospace fonts, the sword application icon, and a simple animated rectangular outline. Paste, file, Browse fallback, optional `tkinterdnd2` drag-and-drop, queued logging, and background processing remain. The main application runs as the current user; the separate setup program requests Administrator access to install files. Results open in the system text editor with an in-app fallback.
- `core.source_input` accepts direct HTTP(S) code links, common GitHub blob/Pastebin pages, and simple `loadstring`/`HttpGet` wrappers. It fetches text only, follows at most four linked layers, caps downloads at 16 MiB with request timeouts, validates redirects, and blocks local/private network targets. It never evaluates fetched source.
- `core.deobfuscator` is a bounded static Luau tokenizer and constant-expression evaluator. It folds supported literal/string, arithmetic, bit32, table-concat, and Base64 forms; unknown/dynamic expressions are retained. It is not a general Luau decompiler.
- `core.formatter` applies whitespace-only formatting while preserving the token stream. It conservatively leaves interpolation strings, Luau `if` expressions, typed function return annotations, and inputs over its size limit unchanged. The pipeline writes a formatted candidate only if a local Luau compiler accepts it in compile-only mode; otherwise it keeps the already-validated candidate.
- `core.pipeline` routes supported Luraph v15 structures to the vendored MIT lifter, which captures VM prototypes/opcodes and lifts their control flow into a readable Luau candidate. Reports include the lifter's function/block/jump counts, unresolved lazy constants, missing-value markers, and runtime functions the backend cannot reconstruct. Unused generated runtime error stubs are removed; any used unresolved runtime helper or unlifted VM block makes the result partial and moves it to a `.candidate.luau` artifact. Generated source receives a compile-only check, which does not prove semantic equivalence. A pinned Luraph sample with a published original source is also executed side by side in Windows AppContainer smoke checks; that validates only the fixture's behavior. Other Luraph versions retain bounded static container extraction and an isolated wrapper attempt; those results are partial. One public Luraph v14.7 fixture was previously used to validate container extraction (`terrorlua/obfuscator-samples`, commit `a6ecd0ea7112c6a65d4b7acba40acc9e280301e3`, file `Luraph/v14.7/001163f72ed972da.lua`, input SHA-256 `9fe7a64c1cf1605002844ca0135fb8daf07ccc192f4bb4e52a405116440718f7`); the unpacker produced a 94,025-byte interpreter stream and a 2,224,577-byte custom-bytecode stream. A single supported fixture is not evidence of broad version/variant coverage.
- MoonSec V3 signatures route to a separate GPL-3.0 helper. It parses recognized wrappers statically, maps supported handlers to standard Lua 5.1 bytecode, then invokes pinned MIT `unluac-rs` for readable source recovery. Key expressions use a restricted AST evaluator; wrapper code is never executed on this route. Output is retained as recovered source only after the Luau compiler accepts it; bytecode/disassembly and explicit partial reports are kept when source lifting fails. Coverage is limited to the helper's known serializer and opcode patterns.
- Other text inputs are statically cleaned and compile-checked, then run in the bounded native Luau worker. The pipeline captures strings passed to real `loadstring`/`load`, compiles them with Luau, and returns executable functions so wrapper code can call them. It explores at most six payload layers and 20 candidates within 90 seconds. A valid source fallback is retained. Each worker run also writes a structured JSONL trace; reports list trace files, event counts, captured chunks, execution outcome, and isolation backend.
- `core.sandbox` requires `protez-native-host`; it fails closed instead of invoking a normal Luau CLI or a fake Roblox runtime. No Roblox Engine globals are fabricated. `io`, `os`, `package`, `dofile`, `loadfile`, and `require` are removed from the Luau worker. Scripts that depend on `game`, `Instance`, Roblox services, HTTP, or remote modules stop when they reach those missing APIs.
- Windows dynamic runs use a no-capability AppContainer, a Job Object with a 768 MiB process/job memory bound and one-process limit, redirected standard streams, and a parent-enforced timeout. Linux runs require `bubblewrap` and `prlimit`; they unshare network and other namespaces, expose the native host and input read-only, bind system runtime libraries read-only, and apply address-space, CPU, file-size, descriptor, and core-dump limits. Dynamic execution is unavailable when these isolation tools cannot start; there is no unsandboxed fallback.
- `native/host.cpp` builds the pinned Luau 0.740 compiler/VM with optimization level 0 and debug level 2. It caps VM allocator use at 256 MiB, dynamic chunks at 16 MiB, and trace events at 25,000 per run by default. Native traces record Luau VM PCs/opcodes, line and frame information, and sampled local values; they do not capture the full register file. `core.tracer` streams the records to rotating JSONL files.
- Protez has family-specific VM lifting for supported Luraph v15 and MoonSec V3 patterns. It does not provide a universal custom-VM lifter. Luau instruction tracing is supplemental behavior evidence and does not itself recover an obfuscator's custom opcodes. Source output is an approximation: names/comments and semantic equivalence are not guaranteed.
- Bytecode inputs (`.luac`, `.lbc`, `.bin`) go through the local `luau-decompiler` CLI in a temporary workspace. The bytecode and recovered source are not executed. The output is syntax-checked and any whitespace-formatted candidate is separately checked in compile-only mode. The CLI has a 30-second default timeout. Frozen Windows builds bundle the CLI from `PumbaaDev/luau-decompiler` commit `ee07098c31e11601a9ca434bc12932a4ded65f7b` and its MIT license notice. Reports claim that provenance only when the active binary's SHA-256 matches the packaged copy; locally discovered binaries are marked unverified. The pinned upstream README documents bytecode versions 3–9; other versions and custom opcode schemes are not promised. Decompilation is lossy: comments and some names are unavailable without debug metadata, and unsupported or shuffled bytecode can yield partial or inaccurate code.
- `installer.py` repairs source-checkout dependencies, Luau tools, and optional family-lifting tools with timestamped logs, subprocess timeouts, and a retry path. Frozen Windows builds bundle the Python/Tk runtime, native host, Luraph/MoonSec backends, both bytecode decompilers, third-party notices, and the GPL helper's corresponding source. The user does not need to install Python, pip, CMake, Rust, or .NET to use the frozen build.
- `.github/workflows/windows-installer.yml` builds the native, Rust, and MoonSec support tools in parallel, then packages x64 `Protez.exe`. The workflow attaches only `Protez.exe` to GitHub Releases.
